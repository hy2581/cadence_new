# 分块控制器 (`tile_controller.sv`)

> 管理 FlashAttention 的双层 tiling 循环。外层遍历 64 个 Q-tile，内层遍历 16 个 KV-tile。为每个 tile 生成 DMA 地址并调度计算。

---

## 常量

```pseudocode
Q分块总数  = SEQ_LEN / TILE_BR  = 256/4  = 64
KV分块总数 = SEQ_LEN / TILE_BC  = 256/16 = 16
Q分块字节  = TILE_BR × HEAD_DIM × 2  = 4×64×2  = 512 字节
KV分块字节 = TILE_BC × HEAD_DIM × 2  = 16×64×2 = 2048 字节
O分块字节  = 同 Q分块字节 = 512 字节
```

> **解析**：FlashAttention 的核心思想是不存储 256×256 的完整注意力矩阵，而是分块计算。TILE_BR=4 和 TILE_BC=16 是面积和性能的折中。

---

## 状态机

```pseudocode
空闲 → 加载Q → 等待Q → 加载K → 等待K → (立即加载V) → 等待V
→ 启动计算 → 等待计算 → 下一个KV → ... → 写回O → 等待O → 下一个Q → ... → 全部完成 → 空闲
```

> **解析**：K 和 V 是串行加载的（先 K 后 V），因为它们共享 DMA 读通道。计算在 V 加载完成后才启动。

---

## 核心逻辑

### 空闲状态

```pseudocode
清 DMA 请求
若 启动信号:
  状态=加载Q, 忙碌=1, Q索引=0, KV索引=0
```

### 加载 Q

```pseudocode
DMA读请求=1
DMA读地址 = Q基址 + Q索引 × 行步长 × TILE_BR
DMA读长度 = Q分块字节
DMA读目标 = Q(0)
状态=等待Q加载
```

> **解析**：地址计算使用行步长(stride)而非 HEAD_DIM×2，支持非紧凑内存布局。

### 加载 K → V → 计算

```pseudocode
等待Q完成后:
  加载K: 地址=K基+KV索引×行步长×TILE_BC, 目标=K(1)
  K完成后立即发V请求: 地址=V基+同偏移, 目标=V(2)
  V完成后:
    计算启动=1
    首个KV = (KV索引==0)        // 告诉softmax初始化m/l
    末个KV = (KV索引==总数-1)    // 告诉累加器做最终归一化
    状态=等待计算完成
```

### KV 循环

```pseudocode
计算完成后:
  若 KV索引是最后一个:
    状态=写回O
  否则:
    KV索引++
    KV缓冲选择取反    // 乒乓切换
    状态=加载KV(下一轮)
```

> **解析**：乒乓缓冲选择每轮翻转，使 DMA 写新数据时计算核心读旧数据，互不冲突。

### O 写回

```pseudocode
DMA写请求=1
DMA写地址 = O基址 + Q索引 × 行步长 × TILE_BR
DMA写长度 = O分块字节
O回写启动=1
等待DMA写完成后: 检查是否还有Q-tile要处理
```

### Q 循环与结束

```pseudocode
若 Q索引是最后一个(63):
  全部完成=1, 忙碌=0, 状态=空闲
否则:
  Q索引++, 状态=加载Q
```
