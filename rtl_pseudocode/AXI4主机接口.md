# AXI4 主机接口

对应 RTL：`axi4_master_if.sv`。

## 模块职责

本模块是 **DMA 与片外/系统总线之间的协议适配层**：把上层给出的「读/写请求、起始地址、字节长度」翻译成符合 **AXI4** 规范的 **INCR 突发** 事务，并驱动读/写通道握手，直到事务完成。

**通俗理解**：DMA 只说「从某地址读/写这么长」，本模块负责按总线数据宽度拆成多拍、发 `AR`/`AW`/`R`/`W`/`B` 握手，并汇报「这一笔读/写做完了」。

## 常量与固定策略

| 概念 | 含义 |
|------|------|
| 每拍字节数 | `数据位宽 / 8`，决定一 beat 能搬多少字节 |
| 大小编码 | `log2(每拍字节数)`，与 AXI `size` 编码一致 |
| 突发类型 | 固定 **INCR**（地址递增） |
| 写选通 | **全选通**（整拍有效） |
| 写响应 | **始终就绪**，避免从机反压 `B` 通道时死锁 |
| ID | 固定 **0**（单 outstanding 简化实现） |

> **解析**：用固定 INCR + 单 ID 可降低主机复杂度；写 `BREADY` 常置 1 是常见简化，前提是系统侧能接受。

## 读通道状态机

**状态**：`读_空闲` → `读_发地址` → `读_接收数据` → `读_完成` → 回到 `读_空闲`。

**变量**：`读总节拍数`、`读节拍计数`（已收到几拍数据）。

### 行为摘要（伪代码）

```text
复位: 读状态=空闲, 地址有效=0, 读数据就绪=0, 读完成=0, 读出数据有效=0

每拍默认: 读完成=0, 读出数据有效=0

读_空闲:
  若 读请求:
    读总节拍数 = ceil(读长度字节 / 每拍字节数)
    主机读地址=读地址, 突发长度=读总节拍数-1, 读地址有效=1
    读节拍计数=0, 状态=读_发地址

读_发地址:
  若 主机读地址就绪:
    读地址有效=0, 读数据就绪=1, 状态=读_接收数据

读_接收数据:
  若 读数据有效且就绪握手:
    读出数据 = 主机读数据, 读出数据有效=1, 读节拍计数++
    若 主机读最后一拍: 读数据就绪=0, 状态=读_完成

读_完成:
  读完成=1, 状态=读_空闲
```

### 分段说明

1. **`读总节拍数`**：字节长度未必整除每拍字节数，用 **向上取整** 保证最后一拍仍覆盖尾部字节（具体字节有效由系统约定，常与 WSTRB/窄传输配合；此处伪代码按「整拍」抽象）。
2. **`突发长度 = 读总节拍数 - 1`**：符合 AXI 里 `len` 为「额外 beat 数」的定义。
3. **`读_发地址`**：等待 `ARREADY`，撤 `ARVALID`，再拉 `RREADY` 收数据。
4. **`读_接收数据`**：`RVALID && RREADY` 时锁存 `RDATA`，用 `RLAST` 识别最后一拍后进入完成态并撤 `RREADY`。
5. **`读_完成`**：打一拍 `读完成` 脉冲（或电平，视 RTL）通知 DMA，然后回到空闲等下一请求。

## 写通道状态机

**状态**：`写_空闲` → `写_发地址` → `写_发送数据` → `写_完成` → `写_空闲`。

### 行为摘要（伪代码）

```text
写_空闲:
  若 写请求: 同上算节拍, 发写地址, 状态=写_发地址

写_发地址:
  若 写地址就绪: 写地址有效=0, 写入数据就绪=1, 状态=写_发送数据

写_发送数据:
  主机写数据 = 写入数据, 写数据有效 = 写入数据有效
  若 写入数据有效: 写节拍计数++, 最后一拍标志 = (写节拍计数==写总节拍数-1)
  若 写数据有效且就绪且最后一拍:
    清写数据有效/最后一拍/写入数据就绪, 状态=写_完成

写_完成:
  若 写响应有效: 写完成=1, 状态=写_空闲
```

### 分段说明

1. **地址相**：与读对称，发 `AW` 通道后等 `AWREADY`。
2. **数据相**：把 DMA 提供的 `写入数据`/`写入数据有效` 映射到 `WDATA`/`WVALID`；用内部计数或 `WLAST` 逻辑标记最后一拍。
3. **完成条件**：必须等 **`BVALID`**（写响应）才置 `写完成`，符合 AXI 写事务在 `B` 通道结束的定义。

---

## 与 DMA 的接口关系

- DMA 产出：**读/写请求、地址、长度**；消费：**读/写完成、读数据有效与数据**。
- 本模块不解析 FlashAttention 语义，只做 **总线事务形状**（beat 数、握手时序）。

如需对照波形，重点看：`AR/AW` 是否在单 outstanding 下不重叠、`RLAST/WLAST` 是否与 `len` 一致、`B` 是否在最后一拍 `W` 之后到达。
