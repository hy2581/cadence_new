# 缓冲系统（详细版）

对应 RTL：`buffer_system.sv`。

## 1. 模块定位

缓冲系统是计算数据通路和外部内存搬运之间的片上存储桥梁，负责四类数据的暂存与供数：

1. Q 分块：DMA 写入，计算核心读取。
2. K 分块：DMA 写入，计算核心读取（双 bank 乒乓）。
3. V 分块：DMA 写入，计算核心读取（双 bank 乒乓）。
4. O 分块：计算核心写入，DMA 读取回写外存。

它本身不做数学计算，只做数据布局、拆包/打包、bank 选择和索引映射。

---

## 2. 参数与容量推导

以下符号和默认值来自 `fa_params.svh`：

- `Q分块行数 = 4`
- `KV分块行数 = 16`
- `头维度 = 64`
- `数据位宽 = 16`（Q8.8）
- `AXI数据位宽 = 128`

内部常量：

1. `每拍元素数 = AXI数据位宽 / 数据位宽 = 128 / 16 = 8`
2. `Q深度 = Q分块行数 × 头维度 = 4 × 64 = 256`（元素）
3. `KV深度 = KV分块行数 × 头维度 = 16 × 64 = 1024`（元素）

按字节换算：

1. Q bank 容量：`256 × 2B = 512B`
2. K 单 bank 容量：`1024 × 2B = 2048B`
3. V 单 bank 容量：`1024 × 2B = 2048B`
4. O 容量：`4 × 64 × 2B = 512B`

---

## 3. 存储体组织

```text
Q存储器[Q深度]
K存储器[2][KV深度]
V存储器[2][KV深度]
O存储器[Q分块行数][头维度]
```

说明：

1. Q 为单缓冲。
2. K/V 各有两个 bank（bank0, bank1），用于乒乓切换。
3. O 采用二维布局，便于计算核心按行写入、DMA 按列组读出。

---

## 4. 地址与数据布局规则

### 4.1 AXI 一拍如何映射到元素

DMA 每收到一拍 `128b` 数据，缓冲系统按 8 个 `16b` 元素拆开：

```text
lane0 = 写数据[15:0]
lane1 = 写数据[31:16]
...
lane7 = 写数据[127:112]
```

并写到连续元素地址：

```text
元素地址 = 基地址(beat索引 × 8) + lane号
```

### 4.2 缓冲写地址的单位

`Q写地址/K写地址/V写地址` 的单位是 beat，不是字节、也不是元素。

例如 `Q写地址 = 3`，实际写入元素区间是 `[24..31]`。

### 4.3 计算读地址映射

计算核心通过 `读步进` 沿 head_dim 方向滑动，每拍取 `并行乘累加数` 个元素：

```text
线性地址 = 行号 × 头维度 + 读步进 × 并行乘累加数 + lane
```

## 5. 各数据通路实现细节

### 5.1 Q 写入（DMA -> Q存储器）

时钟上升沿，当 `Q写使能=1`：

```text
for i in [0..每拍元素数-1]:
  Q存储器[Q写地址×每拍元素数 + i] <= Q写数据切片(i)
```

特征：一次写 8 个元素，线性填充。

### 5.2 Q 读取（Q存储器 -> 计算核心）

组合逻辑连续输出：

```text
Q读数据[行][lane] = Q存储器[行×头维度 + Q读步进×并行乘累加数 + lane]
```

说明：当前 RTL 中 `Q读使能` 未用于门控输出，属于“总是组合读”。

### 5.3 K/V 写入（DMA -> K/V bank）

当 `K写使能=1` 时写 `K存储器[K缓冲选择]`；
当 `V写使能=1` 时写 `V存储器[V缓冲选择]`。

其余映射规则与 Q 写入相同。

### 5.4 K/V 读取（K/V bank -> 计算核心）

```text
K读数据[行][lane] = K存储器[K读缓冲选择][...]
V读数据[行][lane] = V存储器[V读缓冲选择][...]
```

在顶层连接中，读选择通常取写选择的反值：

```text
K读缓冲选择 = ~KV缓冲选择
V读缓冲选择 = ~KV缓冲选择
```

### 5.5 O 写入（计算核心 -> O存储器）

`O写使能=1` 时，一拍把整块 `O写数据[Q分块行数][头维度]` 覆盖写入 `O存储器`。

### 5.6 O 读取（O存储器 -> DMA）

DMA 给出 `O读行号` 和 `O读列组`，缓冲系统打包 8 个元素到一拍 AXI 数据：

```text
for i in [0..7]:
  O读数据[i*16 +: 16] = O存储器[O读行号][O读列组*8 + i]
```

说明：当前 RTL 中 `O读使能` 也未门控组合输出。

## 6. 乒乓缓冲是如何工作的

目标：重叠“搬运下一块 KV”和“计算当前块 KV”。

典型时序（示例）：

1. 周期阶段 A
   - DMA 往 bank0 写入 KV tile n
   - 计算核心从 bank1 读取 KV tile n-1
2. 周期阶段 B（切换）
   - 控制器把 `KV缓冲选择` 翻转
3. 周期阶段 C
   - DMA 往 bank1 写入 KV tile n+1
   - 计算核心从 bank0 读取 KV tile n

好处：

1. 降低同 bank 读写冲突概率。
2. 提高总吞吐，减少“等数据”的空泡。

---

## 7. 与 DMA/控制器协同关系

从 `dma_engine.sv` 可以看到：

1. 读回 Q/K/V 时，`读节拍计数` 直接作为缓冲写地址（beat 索引）。
2. O 回写时，DMA 以
   - `O读行号 = beat / O每行节拍数`
   - `O读列组 = beat % O每行节拍数`
   扫描整块 O。
3. `KV缓冲选择` 来自分块控制器，在 KV tile 边界翻转。

这三点决定了缓冲系统的数据布局必须与 DMA 节拍顺序严格一致。

---

## 8. 实现注意事项（按当前 RTL）

1. 内存体未在复位时清零，仿真初期若先读后写会看到未知值。
2. `Q读使能/K读使能/V读使能/O读使能` 当前不参与组合读门控，更多是上层时序语义信号。
3. 读路径为组合逻辑，多路并行展开，综合后可能形成较长组合路径，需要关注时序收敛。
4. 本模块假设上游给出的地址范围合法，未做越界保护。

---

## 9. 波形核对清单

调试时可按以下顺序检查：

1. Q/K/V 写使能脉冲数是否等于预期 beat 数。
2. K/V 在同一时刻是否发生“同 bank 写 + 读”。
3. `KV缓冲选择` 是否在每个 KV tile 边界翻转。
4. O 回写扫描顺序是否为行优先、列组递增。
5. O 回写总 beat 数是否等于 `Q分块行数 × (头维度/每拍元素数)`。

---

## 10. 一句话总结

缓冲系统本质是“按 AXI 节拍布局的片上 SRAM 编排器”：

1. 对 Q/K/V 做拆包写入与并行读取。
2. 对 O 做整块写入与分组打包读出。
3. 通过 K/V 双 bank 乒乓切换实现搬运与计算重叠。
